# Layout

The annotated tree, and which reference governs each path.

```
README.md              what boma ships and how to install it — the operator-facing entry point
CONTEXT.md             glossary; the canonical vocabulary, and nothing else
PLATFORM.md            the one target platform, asserted at runtime by lib/preflight.sh
LICENSE

docs/
  RECOVERY.md          disaster-recovery runbook, written for someone who is not you
  INGRESS.md           the contract with wardnet, which owns TLS, DNS and the tunnel
  adr/                 the decision record — 0001..0005, consult before re-opening one

lib/                   the shared shell library — see shell-library.md
  boma.sh              the single entry point; sources everything below
  log.sh               log_debug/info/warn/error, die
  util.sh              ensure_dir, atomic_write, generate_passphrase, require_file_mode
  version.sh           version_compare, age_days, soak_satisfied
  notify.sh            the notify seam: notify(), heartbeat()
  preflight.sh         require_root/cmd/arch/systemd/debian, preflight_host
  test/                bats unit tests, one file per library concern — see testing.md

services/<name>/       one directory per service; adding a service adds a directory
services/vaultwarden/  the only service today — see vaultwarden-service.md
  lib.sh               service paths, config precedence, restic plumbing, rollback points
  install.sh           idempotent install/re-install
  update.sh            soak-gated, transactional update
  backup.sh            restic snapshot; nightly, and synchronously before an update
  restore.sh           restore a snapshot — disaster recovery and update rollback
  verify-backup.sh     the restore drill
  systemd/             vaultwarden.service plus the boma-vw-{backup,update,verify} units
  test/                the pytest end-to-end suite and its container — see testing.md

.github/workflows/     the gt pipeline and the release builder — see ci.md
.gt-repo.yaml          repository governance; rendered by `gt repo sync`
.gt.yaml               clone/worktree setup templates
.agentic-toolkit.yaml  the agtk entry manifest; .agentic-toolkit.lock.yaml pins its sources
agentic/               this repo's own agent content: instructions/, references/, rules/
pyproject.toml         the pytest suite's dependency group and options
```

## Conventions that are not obvious from the tree

- **A service is self-contained.** Everything one needs lives under its directory —
  scripts, units, tests. Adding a service changes nothing outside it. Resist the urge to
  hoist something into `lib/` until a second service actually needs it.
- **`lib/` is the only shared code.** A service script sources `lib/boma.sh` through its own
  `lib.sh`, never directly, so the service can pin paths first.
- **Nothing under `agentic/` is rendered output.** The rendered trees — `.claude/`,
  `CLAUDE.md`, `.mcp.json`, `.codex/`, `.agents/`, `AGENTS.md` — are generated by `agtk` and
  gitignored. Edit the definition under `agentic/`, then `agtk sync`.
